# Requirements

Requirements describe system outcomes. A contract alone does not establish that an operation works; verification boundaries are in CURRENT.md and CHECKS.md.

## R-001 — Add different materials
Accept source materials, including a file supplied in a request. Obtain a readable representation, using recognition where necessary.

Criteria: original preserved; readable text linked to it; doubts visible; dates and important fields verifiable; result available for later operations.

Contract: [add-material.md](specs/add-material.md).

## R-002 — Quick orientation
A card should make the material's contents clear; full text is readable without repeating OCR or opening the scan. The history should offer an overview and links to evidence.

Criteria: find materials by type and date; trace a value or statement to its original. No numerical speed target has been set; establish one through actual use.

## R-003 — Prepare for an appointment
Prepare materials for the specialty, purpose, and available history.

Criteria: short summary, relevant timeline, prescriptions and intake with sources, questions for the specialist, attachment links, and explicit data gaps.

Contract: [prepare-visit.md](specs/prepare-visit.md).

## R-004 — Analyze health information
Compare data, identify anomalies and conflicts, and formulate hypotheses, recommendations, and clarification questions.

Criteria: stated coverage; facts separated from interpretation; evidence for observations; no invented unknowns; current sources for external medical recommendations.

Contract: [analyze-state.md](specs/analyze-state.md).
